> **NON-EXECUTABLE ENGINEERING CONTRACT.** This document formalizes the
> engineering contract approved for EXP-019 v1.2 protocol drafting and
> engineering preparation. It registers nothing in `frozen_protocol()`, and
> it authorizes no scientific activation, experimental randomization, image
> generation, run root, allocation, or experimental checkpoint.

- Experiment owner approvals H1, H2, and H3 were explicitly granted on
  **2026-10-22** as proposed in PR #17 and are recorded in
  `docs/drafts/EXP-019-v1.2.0.PROPOSED-DECISIONS-H1-H3.md`.

  to the frozen v1.1.1 definition, fixture, and preregistration; this
  contract changes none of it.

## 3. Normative engineering obligations

A future Stage-2 runtime (PR-6 onward, each separately authorized and
reviewed) must enforce, at minimum:

1. **Schema validation** against the five draft-turned-implementation
   schemas above, with their draft/executable semantics replaced only by a
   future freeze — never by this contract.
2. **Every runtime-reserved check** stated in those schemas: digest
   recomputation against actual bytes; class-C authentication (a digest
   alone never authenticates); attested-vs-recorded source resolution;
   cross-artifact binding of opaque identifier and attempt number;
   temporal ordering (request capture before response capture; action-log
   monotonicity and closure); action-log sequence contiguity; and
   returned-count agreement with actual artifacts.
3. **Evidence rules:** classes A/B/C/D with the six observation statuses;
   qualifying requirements Q1–Q5; class-D material confined to the isolated
   `model_reports` namespace and never authoritative; missing telemetry as
   `not_observable`; no model metadata query and no metadata-recovery path
   anywhere in the implementation (H2).
4. **Decision policy:** the `ADMIT` / `FAILURE` / `INDETERMINATE_FINAL`
   precedence with the per-disposition Q1–Q5 matrix; `PENDING_UNKNOWN`
   strictly non-terminal, remaining operational until an outcome is
   classified; retries only after terminal `FAILURE`, at most two, each
   blocked until the predecessor receipt is externally anchored. An
   unresolved host outcome may be terminalized as `INDETERMINATE_FINAL`
   only through the indeterminate-disposition procedure in the admission
   policy authorized by H3 — at run closure, after every started attempt is
   accounted for — never as a shortcut during the run.
5. **Receipts and checkpoints:** exactly one terminal attempt receipt per
   attempt; separate local-recorded and externally-anchored states; all
   four checkpoint kinds (run-root, per-terminal-attempt, reviewer-freeze,
   terminal `run_disposition` per H3) in the public six-field format
   (`schema_version`, `run_id`, `sequence`, `event_type`,
   `evidence_sha256`, `previous_anchor_commit`). Local finalization and
   external publication are separately recoverable: a locally recorded
   receipt that fails to anchor stays visibly `recorded-unanchored` and is
   externally published later as the same receipt — never rewritten, never
   committed twice — while the run remains paused.
6. **Roles and blinding:** operator, private allocation custodian,
   mapping-blind coordinator, two independent reviewers, and
   adjudicator/analysis with the access boundaries in the roles draft;
   treatment-free reviewer packages; allocation generated only at gate G4
   by the custodian, held only in the private provenance store. Holding
   two roles is recorded as one actor exercising two role obligations: it
   is never represented as personal blindness or as independent
   verification, and the two independent reviewer roles require distinct
   persons for an independence claim.
7. **Activation lockout:** before gate G5 the implementation must be
   incapable of creating an experimental run root, generating an
   allocation, or issuing generation tasking for experimental material.

## 4. What this contract is not

This contract is not a scientific freeze, not a preregistration of an
executable experiment, and not evidence that any implementation exists.
Stage-2 implementation, the non-experimental pilot, the final scientific
freeze, and activation each require their own separately reviewed PRs and
gates (G2–G5) exactly as specified in the freeze-sequencing draft.
