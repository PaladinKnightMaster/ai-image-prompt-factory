# EXP-019 v1.2.0 — Evidence Contract DRAFT

> **DRAFT — NON-EXECUTABLE.** Prospective contract for owner review. Not
> frozen, not registered in `frozen_protocol()`, authorizes nothing.

## 1. Evidence classes

| Class | Meaning | Examples |
| --- | --- | --- |
| A | Frozen protocol requirements | Design constants, frozen prompt digest, requested counts, delivery mode |
| B | Operator-controlled actions and records | Contemporaneous captures and action logs (`operator_recorded`); after-the-fact operator assertions (`operator_attested`) |
| C | Authenticated host-observed evidence, only if genuinely available | Host-signed or otherwise authenticated telemetry |
| D | Model-generated statements about generation behaviour | Unsolicited model claims preserved verbatim in `model_reports` |

Class A values are labels, not observations, and carry no observation
status. Class D can never be upgraded to, substituted for, or used to
overwrite class B or C evidence, and can never occupy an authoritative
observation field.

## 2. Observation statuses

`host_observed` (class C only), `operator_recorded` (class B),
`operator_attested` (class B), `model_reported` (class D, `model_reports`
namespace only), `not_observable`, `not_applicable`.

- An available status requires an actual non-null value and a SHA-256
  `source_ref` identifying the supporting artifact.
- `not_observable` / `not_applicable` require a null value, a null
  `source_ref`, and a class B or C label — never A or D.
- Missing telemetry is recorded, not repaired: a field the host does not
  expose is `not_observable`. It never triggers a model query, a replay, or
  an inference from unrelated timestamps.

## 3. What a digest does and does not prove

A SHA-256 `source_ref` proves only that specific bytes were not altered
after hashing. It does **not** prove the bytes are authentic, that an
attested fact is true, or that evidence is authenticated host telemetry. In
particular, a bare digest never creates class-C evidence: class C requires
an authenticated host source verified by the future runtime, and where no
such source exists the correct record is `not_observable`.

Operator attestations are likewise integrity-bound, not truth-bound. An
`operator_attested` field's `source_ref` must resolve to the attestation
artifact; an `operator_recorded` field's must resolve to a record created
contemporaneously at action time. The two must never be re-labelled into
each other.

## 4. Qualifying class-B evidence

Class-B evidence qualifies only when it is contemporaneous and complete for
the claims it supports:

1. a request capture taken at submission;
2. a response capture taken when the image appears (a distinct, later
   artifact — neither capture may stand in for the other);
3. an action log whose sequence and timing the runtime can verify;
4. artifact digests recomputed by the runtime against the actual bytes;
5. where a field claims `operator_attested`, a hash-bound attestation made
   for that invocation.

Screenshots and transcripts are renderings of the operator's client view.
They are class-B evidence about what the operator did and saw, never
authenticated host-received bytes, and must never be described as such.

## 5. Operator workflow: direct paste, no attachment

1. Open a fresh conversation for the invocation.
2. Paste the exact frozen prompt bytes directly. Attach no file, upload no
   image or reference, and use no chat-starter wrapper or packaged material
   inside the generation conversation.
3. Take the request capture at submission.
4. Submit exactly one generation request.
5. When the image appears, take the response capture; download the artifact
   unchanged and hash it.
6. Perform no edit, regeneration, repair, or follow-up generation in that
   conversation. Do not ask the model to describe, confirm, or report
   host-internal facts.
7. Close the invocation in the action log and complete any attestation.

## 6. Class-D handling

There is **no mandatory post-generation model metadata query** in v1.2 and
**no metadata-recovery workflow** (proposed decision H2). If a model
volunteers statements about generation behaviour, they may be preserved
verbatim — original bytes, digest, and capture time — in the isolated
`model_reports` namespace, labelled `model_reported`. They are never
solicited to repair missing evidence, never resolve conflicts in the
operator's favour, and any conflict between class D and class A/B/C evidence
is counted and disclosed in aggregate (see H1), with the authoritative
evidence unchanged.

## 7. Runtime-reserved validation

The draft schemas (`data/schemas/exp019_v1_2_*.schema.json`) already reserve
the following for a future runtime validator, which must reject artifacts
that fail them even when schema-valid: digest recomputation; class-C
authentication; attested-vs-recorded source resolution; cross-artifact
binding of invocation identifiers and attempt numbers; temporal ordering of
captures and log entries; action-log sequence contiguity and monotonicity;
and returned-count agreement with actual artifacts. No such runtime exists
yet, and none is authorized by this draft.
