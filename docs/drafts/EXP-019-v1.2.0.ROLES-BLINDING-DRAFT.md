# EXP-019 v1.2.0 — Role Separation, Blinding, and Public Provenance DRAFT

> **DRAFT — NON-EXECUTABLE.** Prospective policy for owner review. Not
> frozen, not registered, authorizes nothing.

## 1. Roles

| Role | May access | Access prohibition (absolute; any exception must name its reveal step) |
| --- | --- | --- |
| Operator | Frozen prompts, private allocation, generation conversations, raw artifacts, evidence artifacts | Reviewer scores before submission |
| Coordinator | Invocation schedule in opaque identifiers only, evidence-completeness status, reviewer-package distribution, freeze/anchoring logistics | The allocation or any identifier-to-treatment link, treatment text, reviewer scores before both reviews are frozen |
| Reviewer (two, independent) | Treatment-free reviewer packages only | Treatment, condition, prompt text or digests, generation identifiers, the allocation, other reviewer's scores |
| Adjudicator / analysis | Frozen review records, then the revealed allocation | Unfrozen or partial review records before both reviews are frozen |
| Repository / public | Sanitized public artifacts and provenance commitments | Raw artifacts, private evidence, allocation material |

One person may hold several roles operationally in this project, but the
access separations above define the protocol obligations regardless of who
performs each role. The coordinator in particular sequences work and moves
packages without ever holding the identifier-to-treatment link: generation
tasking is issued in opaque identifiers, reviewer packages are distributed
without allocation material, and the coordinator learns a mapping only at
the same post-freeze reveal as the analysis role, if at all.

Custody is assigned, not implied: the **operator** role generates the
allocation at gate G4 and is its sole custodian in the private provenance
store from generation until reveal; the coordinator handles only opaque
identifiers and never takes custody of the allocation; leak scanning of
public artifacts is a gate duty of whoever prepares a public push, verified
independently at G4; checkpoint commitment is performed by the operator and
verified against the external provenance repository; and the **reveal act**
is performed by the adjudicator/analysis role only after both reviewer
freezes are externally anchored.

## 2. Two distinct blindnesses

- **Mapping blindness:** the link between an opaque invocation identifier
  and its treatment is hidden. This is what reviewer packages, public
  artifacts, tests, and documents must protect.
- **Treatment-content blindness:** reviewers also do not see the treatment
  text, the experimental prompt, or which visible wording was used.

Protecting one does not automatically protect the other; both are required.
Reviewer-facing artifacts therefore contain only an opaque identifier and
raster descriptors: no condition, treatment, variant, prompt, digest of any
prompt, mapping, expected score, or image metadata. Reviewer packages are
rebuilt from decoded pixels with inherited metadata removed, and reviewers
never receive raw output bytes or private bindings.

Both independent review records must be frozen and anchored before the
allocation is revealed to anyone in an analysis role. There is no
post-reveal adjudication beyond the preserved locked analysis rules.

## 3. Protecting a v1.2 allocation

- Any future allocation is generated privately at the final scientific
  freeze (gate G4 in the sequencing draft), after public code and documents
  are frozen.
- It is stored only in the private provenance store, never in public code,
  tests, fixtures, documents, commit messages, or pull-request artifacts
  (including rendered patches and PR bodies).
- Public tests must use synthetic placeholders or derive values from private
  evidence at runtime, exactly as the merged preservation and synthetic
  fixture suites do.
- Public pushes touching experiment material are leak-scanned (identifiers,
  prompts, credentials, private paths) over both the file diff and the
  rendered patch before publication.
- History rewrites of public branches are avoided: an unreachable public
  commit remains retrievable by identifier unless the host purges it, so
  prevention is the primary control.

## 4. Public provenance limitations (to be published with any v1.2 result)

Subject to proposed decision H1, the public provenance state for v1.2 is
`operator_evidenced_host_provenance`, and any public result must state, in
substance:

- generation behaviour rests on operator-controlled records and
  attestations (class B), not on authenticated host telemetry;
- host-internal facts the interface does not expose are `not_observable`,
  and no claim is made about them;
- a digest establishes byte integrity only — never authenticity, factual
  truth, or host observation;
- aggregate counts of conflicts between model-generated statements and
  authoritative evidence are disclosed, with conflicts resolved in favour
  of the authoritative evidence and never by soliciting further model
  statements;
- reviewer blindness is mapping and treatment-content blindness as defined
  above, and any known limitation affecting an earlier run's blindness is
  disclosed retrospectively rather than silently carried forward.

No public artifact may describe operator evidence as host-verified, a
client-view capture as authenticated host bytes, or a model statement as
telemetry.
