isolated synthetic end-to-end harness. It does not register executable
v1.2, create a real allocation or run root, invoke a generation host, or

## 3. Scientific completion vs engineering fixtures

| Path | Disposition | Scientific completion |
| --- | --- | --- |
| Miniature 4-sample fixture | `engineering_scenario_closed` | **False** (never claimed) |
| Incomplete abort | `incomplete` | **False** |
| Full 3×4 (12 admitted, 4 per C/A/B) with dual freezes | `completed` | **True** (synthetic representation only; not experimental findings) |

Technical retries increment finalized invocation count but do not invent
additional scientific samples for a slot. Failed/indeterminate outcomes are
never counted as admitted. Locked analysis is applied only when the 3×4
design qualifies; outputs always set `is_experimental_finding=False` and
`statistical_significance_claimed=False`.

## 4. Successful complete synthetic run (3×4)

Demonstrated by `test_completed_12_sample_scientific_synthetic_run`:

1. Synthetic run context without scientific activation
2. Custodian-only private treatment custody (C/A/B × 4) + mapping commitment
3. Opaque prompt packets to the operator
4. Invocation start → capture → validate → ADMIT → receipt → checkpoint × 12
5. Independent remote verification (including fresh-process re-verify)
6. Treatment-free reviewer packages with distinct randomized orders
7. Two independent reviewer freezes + freeze checkpoints
8. Opening only after both freezes verify
9. Locked descriptive analysis (contrasts, safeguards) — not a simplified substitute
10. Terminal `completed` disposition and full chain verification

## 5. Failure and interruption recovery

Covered by module suites and E2E checks:

- Untrusted anchor claims cannot authorize retries
- Incomplete closure without fabricated review freezes
- Duplicate attempt checkpoint recognition (exactly-once)
- Crash between local finalization and remote publish with durable reload
- Corrupted receipt / mapping commitment fail closed
- Forged class-C never authenticates; class-D conflicts preserved on ADMIT
- Production/network remotes refused for synthetic publication
- Activation lockout while v1.2 is unregistered (runtime `frozen_protocol`)

## 6. Reviewer and custodian isolation

- Custodian holds the mapping; public view exposes only the commitment
- Operator packets carry opaque id + prompt bytes only
- Reviewer packages contain digests and scores only — no treatment,
  condition, prompt, or allocation terminology
- Software role labels are not claimed as personal blindness

## 7. Public / private provenance separation

Public six-field checkpoints only. Private bindings (slot, attempt,
receipt, reviewer id, disposition class) remain in authorized private state.

## 8. Cross-version compatibility

v1.1.1 preservation suite remains green; historical chain untouched;
`exp019_anchor` semantics unmodified. Locked analysis extraction into
`apply_locked_descriptive_analysis` preserves the arithmetic previously
inline in `analyze_exp019`.

## 9. Activation lockout

`frozen_protocol("1.2.0")` remains unknown. G4/G5 unauthorized. Synthetic
publication requires local bare remotes and `AIPF_EXP019_V12_SYNTHETIC_PROVENANCE=1`.
