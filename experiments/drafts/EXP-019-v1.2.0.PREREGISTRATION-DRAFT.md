# EXP-019 v1.2.0 — Preregistration DRAFT

> **DRAFT — NON-EXECUTABLE.** This document is a prospective protocol draft
> prepared for owner review. It is not a frozen preregistration, it is not
> registered in `frozen_protocol()`, and it authorizes no experiment, no
> generation, no metadata query, and no checkpoint. EXP-019 v1.2 must not be
> executed from this draft.

## 1. Purpose of v1.2

EXP-019 v1.1.1 demonstrated that the scientific design could be executed but
that its host-evidence contract was fragile: the protocol asked a model to
self-report host-internal facts, and model-generated statements were at risk
of being treated as telemetry. v1.2 therefore changes **only the evidence and
provenance architecture**. The scientific question, hypothesis, treatment
text, experimental design, review rubric, and mathematical analysis rules are
preserved unchanged from v1.1.1.

## 3. Procedural changes from v1.1.1 (explicit)

| Area | v1.1.1 | v1.2 draft |
| --- | --- | --- |
| Generation input delivery | Prompt/query material could be packaged and attached to the generation conversation | Exact prompt bytes pasted directly; no file attachment, no chat-starter wrapper, nothing packaged inside the generation conversation |
| Post-generation metadata | Mandatory model-generated host-session metadata query in the same conversation | **None.** No mandatory model metadata query (see proposed decision H2) |
| Metadata recovery | Bounded same-conversation recovery replay, plus a degraded-host addendum, after rejected capture | **None.** No metadata-recovery workflow (see proposed decision H2) |
| Evidence model | Model self-report treated through an observed/null sidecar contract | Four evidence classes (A/B/C/D) with six observation statuses; model statements are class D only and can never become host telemetry |
| Artifact identity | Host-reported file path used as a traceability binding | Digest-based artifact identity; paths are class-D claims at most, never identity-bearing |
| Dispositions | Import / reject under sidecar validation, with post-start addenda for exceptions | Three terminal dispositions — `ADMIT`, `FAILURE`, `INDETERMINATE_FINAL` — decided from the evidence contract, with no post-start evidence addenda |
| Telemetry gaps | Missing host values could block import and trigger recovery | Missing telemetry is recorded as `not_observable` and handled by the decision policy; it never triggers a model query or a replay |
| Run termination | Per-attempt checkpoints; run-level closure less explicitly specified | One terminal `run_disposition` event for completed **or** incomplete runs (see proposed decision H3) |
| Randomization handling | Allocation material appeared in public test code during v1.1.1-era work and had to be remediated | No allocation is created by this draft; any future allocation is generated privately at the final scientific freeze (gate G4), committed only to the private provenance store, and never appears in public code, tests, or pull-request artifacts |

## 5. Execution preconditions (all required before any future freeze)

The proposed PR-5–PR-15 sequence and its gates G1–G5 are specified in
`docs/drafts/EXP-019-v1.2.0.FREEZE-SEQUENCING-DRAFT.md`. In summary, and in
this order:

1. **G1** — owner approval of proposed decisions H1, H2, and H3 and of the
   engineering contract.
2. **G2** — a version-pinned v1.2 runtime enforcing every runtime-reserved
   check, synthetically validated against the merged fixture suite, with a
   demonstrated activation lockout.
3. **G3** — a separate non-experimental pilot satisfying the pilot readiness
   draft, formally accepted by the owner, with all pilot material excluded
   from the experiment.
4. **G4** — the final scientific freeze: preserved content re-verified by
   digest, v1.2 only then registered as frozen-but-not-activated, and the
   run allocation generated privately at freeze time, held only in the
   private provenance store, with public-artifact leak scanning of the
   freeze diff.
5. **G5** — explicit owner authorization of activation and run-root
   creation. No earlier approval, merge, or document substitutes for it.

Experimental activation is impossible before G3 and G4 by construction:
before the final freeze there is no registered executable protocol and no
allocation, and before G5 there is no run root. Until all five gates hold,
this document remains a draft and v1.2 remains unregistered and
non-executable.
