## Exact eligibility

Only host-native EXP-019 v1.1.1, the current planned slot, zero attempts/checkpoints and an already
retained, technically evaluable original raster are eligible. Both image and initial raw response
must match explicitly supplied trusted capture SHA-256 values. The original raw sidecar must fail
the unchanged canonical schema **only** for `generated_file_path_status == "observed"` and
`generated_file_path == ""`: the two canonical `anyOf`/`minLength` errors on that field. Every
other schema, slot, receipt, treatment/prompt, generation/reference/output-count, edit/regeneration,
timestamp and query-integrity check remains mandatory. Actual query bytes, manifest hash and
deterministic rendering must agree. The output path is not dereferenced to select a raster.

Truthful explicit operator attestations are required: original conversation permanently unavailable;
initial query collected in the original generation interaction; unchanged initial host response;
unchanged original raster; no metadata replay or replacement; no manual metadata repair; no image
regeneration, edit or replacement; trusted original capture hashes; and no admission informed by
treatment, reviewer scoring or analysis. These claims are operator evidence, not independently signed
host facts. Cryptographic checks prove integrity from preservation/finalization, not authenticity
before the trusted capture. Conversation loss cannot be inferred from missing local files.

Non-evaluable/substitute/tampered images, manually repaired or substituted sidecars, other schema
errors, wrong slot/identity/bindings, alternate/coached queries, prior finalized/attempt/checkpoint
evidence, missing authorization/attestations/marker/rejection, repeat preparation/import, and any
existing metadata-recovery reservation are blocked. The metadata-recovery and degraded paths are
mutually exclusive for a slot, including partial reservations. No reviewer/reveal/analysis artifacts
may exist when degraded admission is prepared or finalized. This does not authorize an image retry,
repair, rescale, crop, recompression, replacement, or metadata replay.

## Evidence and explicit execution

`experiment-degraded-host-prepare` requires the amendment identifier, both expected original hashes
and a strict private attestation JSON. It preserves exact raw bytes, canonical query, complete validator
failure and attestations under `.degraded-host-private/<opaque slot>/`. Its strict
`degraded-evidence.json` is **repository-derived**, never a host response. It declares
`degraded_host_provenance`, invalid raw schema conformance and verified retained scientific bindings.
It binds run/opaque slot/image/raw/query/rejection/attestation hashes, both addenda and the intended
attempt-1 canonical receipt. Preparation leaves the active sidecar, image, run ledger and checkpoint
chain untouched and consumes zero attempts.

`experiment-degraded-host-import` separately requires the same amendment identifier, wrapper,
original staged image/raw sidecar and ordinary operator receipt. All bindings are revalidated before
promotion. Successful finalization moves the original bytes to normal canonical output/sidecar paths,
writes attempt 1 with an explicit degraded marker and wrapper SHA, and appends an immutable
`finalization.json` linking wrapper SHA to the actual receipt file/SHA. The prepared wrapper is not
rewritten: the receipt binds it, and the deterministic finalization link binds the receipt without
a circular hash. Verification checks the exact link contents. Exactly one ordinary external attempt
checkpoint follows successful finalization. A rejected metadata response is not a generation failure.
Ordinary `experiment-import` remains strict and cannot consume a reserved degraded exception.

## Review, analysis and public reporting

Invalid/unadmitted evidence cannot enter the ledger, review or analysis. Normal admitted host evidence
continues to satisfy the canonical raw schema and the legacy `provenance_valid: true` result contract.
Degraded results instead require `binding_integrity_valid: true` plus a strict aggregate
`host_provenance` qualification: affected and normal sample counts, invalid raw schema conformance,
second post-start addendum identity, preserved raster/scientific bindings and reduced host-path
traceability/provenance strength. They cannot claim unqualified `provenance_valid: true`.

An admitted degraded raster participates in the same twelve-image, two-reviewer blinded pixel review.
No marker, rejected response, host ID, conversation-loss fact or validator error enters reviewer-facing
files. It contributes once with the same numerical weight. Hypothesis, fixture, mechanism, common
prompt, C/A/B treatment wording/mapping/order, replicate count, retry policy, rubric, reviewers,
scoring, diagnostics, TERM_REALIZATION_FAILURE, ceiling/floor/reviewer ambiguity/side-effect veto,
delta bands, pairwise directional safeguard and release interpretation rules remain frozen.
Degradation alone causes no scoring penalty, exclusion or forced inconclusive classification.

The allowlisted `experiment-sanitize-exp019` export recomputes verified analysis and publishes only
aggregate numerical outcomes, safeguards and provenance qualification. It excludes private paths,
raw metadata, host/generation IDs, hashes of private evidence, opaque sample IDs and reviewer records.
All final interpretation, including supportive interpretation, must disclose the affected count and
state that it comes from an amended run with degraded-host-provenance samples and reduced host-path
traceability; retained image/query/receipt/treatment integrity does not restore the missing host trace.

## External commitment and scope

The existing six-field checkpoint format is unchanged. Its evidence digest binds canonical receipt,
image, raw sidecar, query and normal ledger evidence. The receipt binds the wrapper SHA; the wrapper
binds preserved raw/rejection/query/attestations and both amendment identities/hashes. The finalization
link is derived entirely from anchored receipt/wrapper identities and is checked exactly. These private
fields are not added to the external checkpoint. Preexisting root and attempt digests remain unchanged.

Implementation validation uses synthetic fixtures only. This addendum does not import the blocked
real raster, generate any image, reveal treatment, score/analyze a real run, create a real checkpoint,
advance a slot, reuse excluded historical material, or change the historical v1.1.0 run.
